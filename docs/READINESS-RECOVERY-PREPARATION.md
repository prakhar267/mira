## Investigating the local runtime crash

Installed Wrangler 4.127.1 wraps some serialized proxy errors in an Error with an empty message, keeping the original under `cause`. Its normal console can therefore be blank while its debug log contains the cause. This identifies why the console was unhelpful, **not the root cause of the failed homepage request**. HTML postprocessing and downstream connection failure remain hypotheses until the cause is captured.

The isolated smoke helper now gives Wrangler an exact log path inside its own temporary directory, keeps log sanitization enabled, and retains at most 64 KiB of debug-log tail plus 16,000 console characters on failure. It never reads global user logs or inherits owner credentials. GitHub retains that structured failure evidence. [Cloudflare documents the logging environment variables](https://developers.cloudflare.com/workers/wrangler/system-environment-variables/).

CI now requires three fixed independent cold starts of the built artifact. The **first failure stops the job**; this is not retry-until-green. Every run still checks the inference refusal, full public smoke and release identity. No deployment guard is skipped, artifact rebuilt after verification, or dependency upgraded based on an unconfirmed cause.

[PR CI 34818501864](https://github.com/prakhar267/mira/actions/runs/34818501864) passed the workspace, Worker and 90 browser checks; its first artifact cold start passed 5/5, and the second reproduced the homepage 500 and proxy shutdown. ### Isolated five-second proxy regression

[Diagnostic-only CI 34822545296](https://github.com/prakhar267/mira/actions/runs/34822545296) subsequently passed, including all 90 browser cases and three artifact cold starts. That did not erase the intermittent failure. A separate local reproduction then sent static JavaScript GETs exactly 5,000 ms apart, measured from **send time**, with no intervening health requests. Wrangler's ProxyWorker returned a 216-byte `Network connection lost` HTTP 500 and shut down. It also failed with fresh client sockets, so this was not merely the browser reusing its own expired connection. Waiting five seconds *after* the preceding response had missed the race. [Cloudflare's upstream issue describes this same dev-proxy timing boundary](https://github.com/cloudflare/workers-sdk/issues/14641).

The committed regression sends six fixed requests on that cadence, checks every response against the actual compiled asset's SHA-256, and fails on the first non-200, byte mismatch or network error. Against the old runner it reproduced HTTP 200 at 0 and 5,000 ms, then HTTP 500 at 10,000 ms. It never retries. Every one of the three independent CI cold starts retains its own cadence and public-smoke evidence under `apps/web/test-results/artifact-N`, including partial cadence results on failure.

The replacement harness uses the **already installed, locked** Miniflare/workerd runtime and SDK configuration conversion, preserving compiled application modules, assets and SQLite bindings. It does not patch a dependency, rebundle the app, replace application routes or change production networking. A narrow localhost Node HTTP adapter forwards streaming requests/responses through Miniflare's supported `dispatchFetch` instead of Wrangler Dev's extra ProxyWorker hop. Runtime outbound fetches are blocked, credentials are explicitly excluded, and the server-side inference refusal is still checked before readiness. This is a local acceptance-harness change, not a claim that production voice latency or provider quality has changed.

The direct workerd control passed 20 fixed-cadence requests over 95 seconds with fresh sockets. The final Node adapter also passed 20/20 over 95 seconds using reused client connections. Eleven focused tests cover streaming in both directions, disconnect cancellation, response backpressure, multiple cookies, decoded content lengths, redirects/HEAD, exact module/asset bytes, native asset headers, real durable SQLite and KV operations, version metadata, ignored source secret files and blocked outbound fetch. The full compiled browser suite and final Linux CI remain required for this integrated revision.
